# FlowMate v3.3.0 fixes

## Database
- Added an initialized `data/project_assistant_js.db` to the distributed ZIP.
- Added `npm run db:init` / `scripts/init-db.js`.
- Local SQLite persists on the same machine across restarts.
- Turso remains the production database path for durable Render deployment.

## Chat
- Sender immediately renders the server-confirmed message after POST.
- New authenticated SSE endpoint: `GET /api/channels/:channelId/events`.
- Other users in the same channel receive new messages live without refreshing.
- A 10-second polling sync remains as a fallback for proxies/networks that interrupt SSE.

## Theme
- Fixed startup/runtime localStorage mismatch (`orbit_theme` vs `flowmate-theme`).
- Saved theme is applied before the stylesheet paints.
- Runtime and startup both set the same theme preference and resolved theme.

## AI task planning
- Normal non-trivial project briefs target exactly 6 main workstreams, never more than 6.
- AI asks for 7–12 direct subtasks per workstream when scope supports it.
- Heavy subtasks can contain 3–8 nested execution steps.
- Manager assignments are diversified when several people are available.
- Work items are balanced so available members are covered when enough generated work exists.

## Manual task division
- Top-level manual task owner is labeled Manager / Owner.
- New task supports `Create & divide`.
- Existing task supports `Manual divide`.
- Bulk manual breakdown lets the user create multiple subtasks, select assignees/priorities/estimates, and add nested steps with their own assignees.
- Parent-task creation is validated to stay inside the same List/project hierarchy.

## Verification
- Full automated suite: 30/30 passing after v3.3 changes.
- Targeted real-time test opens the SSE stream with one user and confirms a message posted by another user arrives without refresh.
