# FlowMate v3.2.2 — Centered Auth + Deeper AI Work Breakdown

## Auth UI fix
- Authentication is now forced into a single full-viewport grid column.
- The login/signup card is horizontally and vertically centered on desktop and mobile.
- Sign in / Sign up tabs are centered inside the card.
- This fixes the legacy two-column auth grid rule that was still affecting the new centered layout.

## AI Project Planner upgrade
- AI is instructed to create **4–6 main workstreams**, never more than 6.
- Each main workstream should normally contain **5–10 detailed direct subtasks** when supported by the brief.
- Direct subtasks include a complexity level: `small`, `medium`, or `heavy`.
- Heavy/multi-step subtasks can be subdivided into **2–6 nested child tasks**.
- Hierarchy supported by the generated plan:
  - Main task / workstream — manager
  - Direct subtask — assignee
  - Nested execution step — assignee
- AI continues to use only supplied workspace people and considers workload/capacity/status.

## Human review
- Main tasks: accept/reject/edit.
- Direct subtasks: accept/reject/edit.
- Nested steps: accept/reject/edit.
- Accept All / Reject All now applies recursively to all three levels.
- Nothing is written to the project until `Create accepted plan` is used.

## Persistence
- Nested work is stored as real `tasks.parent_task_id` relationships.
- Heavy-work child tasks are persisted as children of their direct subtask, not flattened text.
- List view displays hierarchy depth and a `STEP` badge for nested execution items.
- Manual `Add subtask` still works on any existing task, so users can subdivide further manually.

## Verification

- Planner test verifies:
  - maximum 6 main workstreams,
  - 5+ detailed subtasks in fallback planning,
  - nested heavy-task subdivision,
  - review rejection at main/subtask/nested levels,
  - database persistence of the three-level hierarchy.
